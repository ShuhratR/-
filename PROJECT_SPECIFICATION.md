# 1. Общее описание проекта

## 1.1 Название

«Шейх Кебаб».

## 1.2 Тип проекта

Статический адаптивный одностраничный сайт-каталог ресторана с:

- каталогом блюд;
- поиском и категориями;
- подробной карточкой блюда;
- локальной корзиной;
- расчётом доставки;
- формой оформления;
- формированием заказа для WhatsApp.

Это frontend-only решение. Backend, база данных, личный кабинет, API и административная панель отсутствуют.

## 1.3 Бизнес

Сайт создан для ресторана/доставки еды в Душанбе. В меню представлены роллы, пицца, бургеры, фастфуд, салаты, супы, сеты, шаурма, напитки и десерты.

## 1.4 Решаемая проблема

Клиенту не нужно:

- регистрироваться;
- звонить и диктовать заказ;
- вручную перечислять блюда;
- самостоятельно считать сумму;
- переходить между несколькими страницами.

Клиент собирает заказ в интерфейсе, вводит контактные данные, после чего сайт открывает WhatsApp с готовым структурированным сообщением.

## 1.5 Работа для клиента

1. Клиент открывает сайт.
2. Видит бренд, описание, часы работы, условия доставки и CTA.
3. Переходит к меню.
4. Ищет блюдо или выбирает категорию.
5. Может переключить сеточный и списочный вид каталога.
6. Открывает компактную модальную карточку блюда.
7. Добавляет позиции и меняет количество.
8. Открывает корзину.
9. Видит стоимость блюд, доставки и итог.
10. Заполняет форму.
11. Отправляет подготовленный заказ в WhatsApp.

## 1.6 Работа для владельца

Владелец получает в WhatsApp текст, содержащий:

- перечень блюд;
- количество каждой позиции;
- стоимость каждой строки;
- сумму блюд;
- стоимость доставки или отметку о самовывозе;
- итог;
- имя;
- телефон;
- способ получения;
- адрес при доставке;
- желаемое время;
- способ оплаты;
- комментарий.

Сайт не фиксирует заказ на сервере. Получение сообщения в WhatsApp является единственным каналом передачи заказа.

## 1.7 Отличия от обычного информационного сайта

- каталог генерируется из массива данных;
- есть клиентское состояние;
- корзина сохраняется между перезагрузками;
- форма также сохраняется между перезагрузками;
- производится динамический расчёт;
- есть модальные слои;
- есть интеграция с Web Share API и Clipboard API;
- заказ сериализуется в WhatsApp URL;
- интерфейс учитывает safe-area iPhone;
- статус «открыто/закрыто» вычисляется по времени Душанбе.

## 1.8 Главная бизнес-логика

`товары × количество → сумма блюд → доставка по правилам → итог → данные клиента → WhatsApp-сообщение`.

## 1.9 Главный сценарий

`Главная → Меню → Поиск/категория → Товар → Корзина → Оформление → WhatsApp`.

# 2. Полный путь пользователя

## 2.1 Схема

```text
Точка входа
↓
Главная страница
↓
Hero и условия
↓
Популярные блюда / каталог
↓
Поиск, категория, сетка или список
↓
Модальная карточка блюда
↓
Корзина
↓
Форма оформления
↓
WhatsApp
```

## 2.2 Этапы

### Точка входа

- Источник может быть любым: ссылка, QR-код, социальная сеть, закладка.
- Специальная аналитика источника отсутствует.
- URL товара отдельно не формируется.

### Главная

- Пользователь видит sticky-header с брендом, WhatsApp и корзиной.
- Hero сообщает нишу, город, преимущества и часы работы.
- Статус ресторана пересчитывается раз в минуту.
- Закрытый статус не запрещает добавление и отправку заказа.

### Переход в меню

- Кнопка «Смотреть меню» ведёт к `#menu`.
- Используется плавная прокрутка CSS.
- Прямой скролл страницы также доступен.

### Поиск

- Поиск запускается при каждом `input`.
- Строка приводится к нижнему регистру.
- `ё` заменяется на `е`.
- Пробелы по краям удаляются.
- Проверяются название, категория и описание.
- При непустом запросе активная категория автоматически становится «Все».
- Поиск глобальный и не ограничивается ранее выбранной категорией.

### Категории

- На широких экранах категории показаны кнопками-чипами.
- До `980px` используется компактный dropdown.
- Категории вычисляются из товаров через `Set`.
- Выбор категории очищает поиск.
- После выбора интерфейс прокручивается к началу результатов.
- Закрытие dropdown происходит после выбора или клика снаружи.

### Просмотр товара

- Клик по фотографии или телу карточки открывает модальное окно.
- Фон затемняется и размывается.
- URL не меняется.
- Окно закрывается крестиком, кликом по фону или `Escape`.
- Клик внутри карточки её не закрывает.
- В окне доступны фото, метка, категория, название, описание, размер, цена, добавление/количество и «Поделиться».

### Добавление

- Кнопка `+` вызывает `changeQuantity(id, 1)`.
- Если товара не было, создаётся запись в объекте корзины.
- Если был, количество увеличивается.
- Показывается toast «Добавлено в корзину».
- Каталог, корзина и модальная карточка синхронно перерисовываются.

### Изменение количества

- `+` увеличивает количество на 1.
- `−` уменьшает на 1.
- При результате `0` или меньше ключ удаляется.
- Отдельного отрицательного количества быть не может.

### Удаление

- Крестик в строке корзины сразу удаляет товар независимо от количества.
- Подтверждение удаления отсутствует.
- Кнопки «Очистить всю корзину» нет.

### Расчёт

- Количество в индикаторах — сумма всех единиц, а не число уникальных позиций.
- Подытог — сумма `цена × количество`.
- Доставка определяется выбранным способом получения и порогом.
- Итог — подытог плюс доставка.

### Оформление

- При пустой корзине кнопка disabled.
- При непустой корзине открывается modal.
- Заполняются имя, телефон, получение, адрес, время, оплата, комментарий.
- На мобильном активное поле центрируется после появления клавиатуры.
- Поля имеют `16px`, чтобы Safari iPhone не увеличивал страницу.

### WhatsApp

- Форма проходит HTML-валидацию и пользовательскую проверку телефона/адреса.
- Формируется многострочное сообщение.
- Сообщение кодируется.
- Открывается `https://wa.me/...` в новой вкладке/приложении.
- Сайт показывает toast о подготовке заказа.

### После отправки

- Корзина не очищается.
- Форма не очищается.
- Сайт не знает, отправил ли пользователь сообщение.
- Нет номера заказа, статуса, оплаты на сайте или страницы успеха.

## 2.3 Ошибки и состояния пути

| Ситуация | Реакция |
|---|---|
| Ничего не найдено | Блок «Ничего не нашли» |
| Пустая корзина | Текст пустого состояния, checkout disabled |
| Короткий телефон | Нативная ошибка с пользовательским текстом |
| Короткий адрес | Нативная ошибка при доставке |
| Самовывоз | Адрес скрывается и перестаёт быть required |
| Повреждённый JSON корзины | Возвращается пустой объект |
| Повреждённая сохранённая форма | Ключ формы удаляется |
| Share отменён | Ничего не показывается |
| Share завершился ошибкой | Toast об ошибке |
| Popup WhatsApp заблокирован | Toast с просьбой разрешить открытие |

# 3. Структура страницы

## 3.1 `<head>`

- UTF-8.
- `viewport-fit=cover` для iPhone.
- `theme-color: #a91418`.
- favicon как встроенный SVG data URL с буквами «ШК».
- SEO title и description.
- Google Fonts.
- `style.css`.

## 3.2 Sticky Header

Содержит:

- ссылку бренда на `#top`;
- круглый текстовый знак «ШК»;
- название и подпись;
- ссылку WhatsApp;
- зелёный статусный кружок;
- кнопку корзины;
- счётчик единиц.

На мобильном:

- текст WhatsApp скрыт, остаётся круглая кнопка-индикатор;
- десктопная кнопка корзины скрыта;
- корзину заменяет нижняя floating-панель.

## 3.3 Hero

Содержит:

- eyebrow «Готовим после заказа»;
- главный заголовок;
- описание;
- CTA «Смотреть меню»;
- CTA WhatsApp;
- динамический статус;
- график `11:00–23:00`;
- стоимость доставки `0–20 сомони`;
- бесплатную доставку от `150 сомони`;
- фото товара №18;
- декоративное кольцо, badge «ХИТ» и символы.

## 3.4 Benefits

Три карточки:

1. Свежие продукты.
2. Быстрая доставка.
3. Удобный заказ через WhatsApp.

## 3.5 Menu Section

Порядок:

1. Заголовок «Наше меню».
2. Горизонтальный блок «Популярное».
3. Sticky-панель инструментов.
4. Количество результатов и сброс.
5. Сетка/список товаров.
6. Пустое состояние.

## 3.6 Популярные

- Жёстко выбраны ID `[18, 4, 13, 1, 7]`.
- Состав не определяется меткой автоматически.
- На десктопе есть стрелки.
- На мобильном стрелки скрыты, используется свайп.
- Горизонтальная прокрутка использует scroll snap.

## 3.7 Панель меню

Содержит:

- поиск;
- desktop-категории;
- mobile/tablet dropdown;
- переключатель сетка/список.

Панель sticky:

- `top: 76px` на desktop;
- `top: calc(68px + safe-area-top)` на mobile.

## 3.8 Каталог

Карточка:

- фото;
- метка;
- категория;
- название;
- описание;
- размер/вес;
- цена;
- кнопка добавления или quantity-control.

## 3.9 How It Works

Три шага:

1. Выберите блюда.
2. Укажите детали.
3. Отправьте заказ.

## 3.10 Footer

- бренд;
- слоган;
- город и график;
- WhatsApp CTA.

## 3.11 Floating Cart

- Показывается только на мобильном и только при непустой корзине.
- Содержит количество и итог.
- Учитывает нижнюю safe-area.

## 3.12 Cart Drawer

- Desktop/mobile drawer справа.
- Overlay.
- Заголовок и закрытие.
- Список товаров.
- Прогресс бесплатной доставки.
- Сумма, доставка, итог.
- Кнопка оформления.

## 3.13 Checkout Modal

- Центрированное светлое окно.
- Прокручивается независимо.
- Содержит форму.
- Закрывается крестиком, кликом по свободному фону или `Escape`.

## 3.14 Product Modal

- Компактное окно поверх каталога.
- Desktop: фото слева, информация справа.
- Mobile: фото сверху, информация снизу.
- Клик по backdrop закрывает.
- URL не меняется.

## 3.15 Toast

- Один общий элемент `#toast`.
- Текст заменяется динамически.
- Автоскрытие через `1700ms`.

# 7. Логика корзины

## 7.1 Структура

```js
state.cart = {
  [productId]: quantity
}
```

Пример:

```json
{"1":2,"9":1}
```

Одинаковость определяется только числовым ID. Вариантов нет.

## 7.2 Добавление и удаление

```text
next = currentQuantity + delta
если next <= 0 → удалить ключ
иначе → сохранить next
```

Крестик строки выполняет прямой `delete state.cart[id]`.

## 7.3 Формулы

```text
count = Σ quantity
subtotal = Σ (product.price × quantity)
delivery = delivery-rule
total = subtotal + delivery
```

## 7.4 Сохранение

Ключ:

```text
sheikh-kebab-cart
```

После любого изменения:

1. объект сериализуется JSON;
2. сохраняется;
3. каталог перерисовывается;
4. корзина перерисовывается;
5. открытая карточка товара обновляется.

После reload корзина восстанавливается.

## 7.5 Невалидные данные

- Ошибка JSON → пустая корзина.
- Неизвестные ID отбрасываются `getCartItems`.
- Количество `<= 0` отбрасывается.
- Тип quantity строго не нормализуется; предполагается собственная корректная запись сайта.

## 7.6 Отображение

- Header: общий count.
- Floating cart: count и total.
- Карточка: add или quantity control.
- Drawer: изображение, название, сумма строки, controls, remove.
- Product modal: add или «N в корзине».

## 7.7 Открытие и закрытие

- `openCart`: снимает `inert`, добавляет `.open`, блокирует body, фокусирует close.
- `closeCart`: обратные действия и возврат фокуса.
- На desktop drawer имеет ширину до `470px`.
- На mobile drawer занимает до 100% ширины.

## 7.8 Ограничения

- Нет максимального количества.
- Нет проверки доступности.
- Нет серверной цены.
- Нет очистки всей корзины.
- Нет корзины между разными устройствами.
- Нет вариантов и добавок.
- Корзина не очищается после WhatsApp.

# 8. Логика доставки

## 8.1 Конфигурация

```js
deliveryPrice: 20
freeDeliveryFrom: 150
```

Валюта: сомони.

## 8.2 Типы получения

- `delivery` — доставка, выбрана по умолчанию.
- `pickup` — самовывоз.

## 8.3 Формула

```text
если fulfillment != delivery:
  delivery = 0
иначе если subtotal == 0:
  delivery = 0
иначе если subtotal < 150:
  delivery = 20
иначе:
  delivery = 0
```

## 8.4 Прогресс

```text
percentage = min(100, round(subtotal / 150 × 100))
```

Если порог достигнут:

```text
«Доставка будет бесплатной»
```

Иначе:

```text
«До бесплатной доставки {150 - subtotal} сомони»
```

## 8.5 Самовывоз

- поле адреса скрывается;
- `required` снимается;
- доставка становится 0;
- итог пересчитывается;
- в WhatsApp пишется «самовывоз».

## 8.6 Не реализовано

- районы;
- разные тарифы по району;
- радиус;
- расстояние;
- карта;
- геолокация;
- минимальная сумма;
- адрес самовывоза;
- расписание по дням;
- запрет заказа вне графика.

Диапазон «0–20 сомони» в Hero — маркетинговое описание фактических двух значений: бесплатно или 20.

## 20.2 Реализовано частично

- Статус «закрыто»: отображается, но не ограничивает заказ.
- Share: передаёт общую URL страницы, а не глубокую ссылку конкретного товара.
- WhatsApp failure: есть toast, но нет копирования заказа.
- Доступность modal: есть `role`, `aria-modal`, `inert`, focus close и возврат фокуса, но нет полного focus trap.
- SEO: title/description есть, но нет Open Graph, schema.org и canonical.
- Error handling изображений: alt есть, fallback нет.
- Success заказа: есть toast подготовки, но нет подтверждения отправки.
- README: существует, но частично не соответствует текущей версии.

## 20.3 Обсуждалось, но не реализовано

- отдельные URL товаров были временно реализованы, затем сознательно убраны;
- просмотр товара full-screen был заменён компактной карточкой;
- кнопка звонка была убрана по требованию;
- touch tilt обсуждался/реализовывался, затем убран из-за конфликта со скроллом;
- анализ референса предполагал варианты, нутриенты, skeleton и расширенный checkout, но они не добавлены;
- установка отдельного VS Code mobile extension обсуждалась, вместо этого использовались Live Preview и браузерные размеры.

## 20.4 Что можно улучшить

Приоритет 1:

# Приложение B. Критерии точного воспроизведения

Новая реализация соответствует этому шаблону, если:

- работает без регистрации;
- имеет один основной URL;
- каталог строится из данных;
- поиск глобальный;
- категории адаптивны;
- товар открывается поверх каталога;
- корзина сохраняется;
- расчёт прозрачен;
- checkout сохраняется;
- заказ открывается в WhatsApp;
- мобильный Safari не увеличивает поля;
- safe-area не перекрывает fixed UI;
- отсутствующие функции не выдаются за реализованные.
